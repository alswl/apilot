# Apilot 工作台人工审查

以完整工作台为默认范围，报告记录被审查的 Git 提交、范围和数据模式。只审单页也可以，超出本次走查范围的检查保留为 `not_verified`。评分的权重和通过线由 [checks.json](checks.json) 定义。

| ID | 满足这些条件记为 `pass` | 可复现证据 |
| --- | --- | --- |
| `navigation-return` | 任务能从列表打开、展开和收起。面包屑、可见返回和 Esc 都能返回正确层，恢复任务、分页、筛选、焦点及侧栏状态。由关联任务返回时恢复原详情 | 用 `o` 打开详情，打开关联任务，连续按 Esc。分别重试全宽详情和折叠后的侧栏 |
| `keyboard-focus` | `⌘1` 导航。任务集合用 `j/k` 跨页，`o` 或 Return 打开，`/` 聚焦搜索，`n` 打开新建入口。编辑文字不触发单键命令。弹窗和编辑层优先处理 Esc | 在列表、输入框、助理弹窗和标签编辑中各按一次对应键，记录焦点和命令结果 |
| `layout-reachability` | 在 1190 × 730、860 × 580 和 680 × 580 pt 下，列表、筛选、分页及详情操作可达。切换左右与上下布局时保留选区、查询和草稿。自动分页按实际列表高度更新 | 每个尺寸分别走查简中和英文，包含长任务名、零结果和末页，记录实际窗口尺寸 |
| `source-actions` | 两种来源的复选框、状态菜单、标签修改、连接实例配置和日志符合各自能力。以实际能运行的模式验证来源写入；fixture 可验模拟交互，不能据此确认真实写入 | 对 GitHub Issues 和 Obsidian Tasks 分别操作并记录字段与状态变化。没有来源操作的页面可标 `not_applicable`，全工作台报告必须检查 |
| `sessions-and-feedback` | Now 进入即有简报，正文依据平铺。空新会话可复用。达到 10 条时可折叠，并从会话库搜索重开。全局助理启闭后恢复上下文，连接和状态栏能读出同步状态 | 记录第 9/10 条和搜索重开的结果。记录在任务选中时开关全局助理后的焦点和上下文 |
| `visual-hierarchy` | 窗口层级、字号、颜色、间距和交互状态符合项目 UI 标准。连接用品牌标识，详情标签有选中底线，辅助动作图标化。表格和详情优先显示对象信息 | 每个改动页提供可定位截图。标出焦点、悬停、选中、禁用状态和同屏重复标题 |
| `language-and-names` | 英文和简中可切换，常见核心文案完整，长标题和标签保持可读。图标有与对象关联的提示及可访问名称，返回与错误提示语义明确 | 在两种语言走查同一对象，记录工具提示和 VoiceOver 读法。缺少 VoiceOver 时注明待验证 |

逐项填写 `status` 和 `evidence`。后者是一段可定位的观察记录。部分通过和失败项写下操作步骤、期望与实际结果。

- `pass` 表示满足该项全部验收条件。
- `partial` 表示已实际验证且存在局部偏差。关键检查出现任何失败条件时填 `fail`。
- `fail` 表示观察到核心动作不可用、严重偏差或关键检查出现失败。
- `not_verified` 表示还缺少决定结果的证据，写明缺失的测试条件。
- `not_applicable` 只适用于表中明确允许的情形。

用 `python3 scripts/score-workbench-ui.py --template` 获取 JSON 输入模板。评分器输出 JSON，含 `score`、`coverage`、`verdict`、状态计数、逐项得分与待处理 ID。通过得满权重，部分通过得一半，失败和未验证得零。不适用项移出分母。覆盖率按已验证权重计算，失败也算已验证。只在覆盖率为 100%、得分达到 90 且没有关键项失守时得出 `pass`。关键项失败、部分通过或未验证时得出 `blocked`，其余未达标情况为 `needs_work`。退出码 0 表示通过，1 表示有效报告尚未通过，2 表示输入错误。
