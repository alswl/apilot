# apilot 领域模型

这份模型描述 macOS 个人助理工作台的长期产品设计。正式入口提供本地自动化与外部状态观察。工作台模拟模式已能演示任务和助理交互，跨平台集成与插件属于目标设计。术语定义见 [GLOSSARY.md](../GLOSSARY.md)。

## 工作在何处发生

| 语境 | 用户需要知道什么 | 关键关系 |
| --- | --- | --- |
| 工作与来源 | 这件事由哪里承载，实际做到哪了？ | Task（任务）通常通过 Task Mapping（任务映射）对应到平台记录。Source Object（来源对象）也包括可以独立存在的页面、章节、PR 和会话。 |
| 个人关注 | 哪些工作值得我看，什么时候需要我判断？ | Watch（关注）表达用户要持续跟进哪些对象，可以指定对象，也可以按来源属性和对象关系确定范围。对象负责人、关注者和下一步行动人可以是不同的人。 |
| 助理协作 | 我交代了什么，助理交回了什么？ | Assistant Session（助理会话）承载对话；Delegation（委托）记录目标；Artifact（产出物）承载成果。助理可以整理、给出引导，或在授权内采取行动。 |
| 接入与扩展 | 哪些来源可用，能读写哪些内容？ | Connector（连接器）描述某类平台的能力；Connection（连接）指定具体来源、范围和权限；Plugin（插件）是交付新增能力的标准方式。 |
| 本地自动化 | 什么时候触发了什么，结果如何？ | 自动化语境中的 Task（自动化任务）定义可执行工作，Schedule（计划）可以产生 Trigger（触发），受理后形成 Run（运行）。 |

## 任务的身份与同步

工作台任务是对待办工作的抽象。典型路径是接入一条已有任务，直接在 apilot 中查询、组织和管理它。独立的本地任务也是有效任务，可以稍后建立平台映射，也可以一直仅在本地存在。查看或关注一个对象，本身就有价值，无需先给它创建任务。

以跟进退款改造为例，几种关系分别回答不同的问题。

| 关系 | 例子 | 对状态的含义 |
| --- | --- | --- |
| Task Mapping（任务映射） | 工作台里的“补退款验收用例”对应 Jira 的 PAY-42 | 通过这条对应关系，可以定位来源，按连接能力双向同步。 |
| Bind（绑定） | PAY-42 和一条独立接入的 Obsidian 待办代表同一项工作 | 可选主对象，按绑定约定联动状态。解绑保留两条来源记录。 |
| Link（关联） | Codex 会话产出 PR，PR 实现 PAY-42，工单引用 Obsidian 的验收章节 | 保留各对象的状态。PR 已合并与业务已验收是两条可以分别核对的事实。 |

接入以授权的 Sync Scope（同步范围）为边界，覆盖范围内对象的可用元数据，包括他人负责的工作。平台原生字段参与组合筛选，图文、附件和可写字段随来源能力而定。从本地修改到来源确认之间，界面应区分待回写、已确认和冲突。连接上次成功同步的时间决定用户能把哪些信息当成最新进展。

### Syncer（同步器）的职责

Syncer 是工程组件。每个 Connection 有独立的同步进度和待回写变更。建议由 Syncer 统一负责首次读取、后续刷新、断点恢复和结果核对；Connector 负责平台特有的读取、写入和确认方式。开放协议应让连接器声明支持的字段、写入动作、增量读取与版本检查能力。只读连接也可以持续同步进展。

连接器协议声明如何识别当前用户、如何发现变更。例如个人 Obsidian vault 按本人语境处理待办，有账号的平台则用当前连接对应的平台身份。该规则用于解释人与任务的关系，接入范围内他人负责的对象也可以同步和关注。

首次读取建立本地基线。后续可由本地文件变化、来源 Webhook 或定时增量读取触发刷新。建议 Syncer 在变更落地后保存进度，用来源标识和版本去重，并按来源当前状态处理乱序。Mac 休眠、漏收 Webhook 或接收端不可达时，从已确认进度补读；来源缺少增量接口时按范围重新核对。Webhook 的接收部署方式留待连接器设计确定。

同步范围内的来源变化落地后，关注和助理分析可以各自使用。用户或获授权的 Agent 发起修改时，本地先记录修改意图和依据的来源版本，来源确认后更新同步结果。写入结果未知时，先按连接器能力核对，缺少可靠依据则标记待核对，以免重试造成重复创建。绑定任务的状态传播由绑定约定发起，Syncer 分别跟踪各目标的回写，并识别自己写回后重新读到的变化。

例如，离线时将截止日由周五改为周四，重连后发现同事已在来源改为下周一。Syncer 应同时保留本地意图和来源当前值，供用户直接选择。任务详情呈现这次修改的结果，「连接」呈现整体同步进度，CLI 可查询相同状态。

## 从变化到个人注意力

用户交代“帮我关注本季度发布的所有 PR，轮到我评审时再提醒”。发布范围决定持续跟进哪些对象，新加入该发布的 PR 也在其中。评审请求决定何时提醒用户。同一句交代可以通过 CLI 或助理对话生效。

工作台重点呈现新增、高优和进展。一项刚建立的高优任务可以同时符合前两项。建议用首次同步建立的基线识别新增，用来源优先级或有依据的助理判断解释高优，用前后状态和产出变化说明进展。用户在原平台处理后，Syncer 更新本地状态，助理据此更新已过时的提示。

“忽略”仅作用于选中的分析反馈。任务继续可见、继续同步，既有关注继续生效，后续实质变化仍可产生新的反馈。首次读取或重复收到同一变更时应避免重复打扰。

在现有观察模型中，Observer（观察器）每次检查产生 Observation（观察结果）。检查超时表示这次没读到状态，外部 Agent 的实际工作结果仍待核对。Attention Event（关注事件）记录值得留意的变化，Notification（通知）是一次提醒。用户确认已读、授权一个动作和解决业务问题分别有自己的含义。

## 助理、资料与信任边界

用户在全局对话框交代“周五前准备客户简报”。助理借助 Pi 这一 Agent Harness（Agent 执行框架）组织工具和步骤，按授权调用 AI Provider（推理服务提供方）。外部 Agent Session 可以提供交付进展。助理自己的对话可从历史继续，简报可从工作台独立打开。

| 助理可用的资源 | 在这个委托里的作用 |
| --- | --- |
| Knowledge Base（知识库） | 查阅需求、验收标准和历史资料。可作为本地长期记忆的载体。 |
| Memory（记忆） | 找回有来源的约定，例如用户上次答应客户核实老订单退款。可通过接入的记忆系统使用。 |
| Writing Library（写作库） | 取得客户简报范例和写作要求。 |
| Assistant Library（助手库） | 选择已配置的专用助手，例如调用写作助手生成简报。 |

用户可以只要求分析，也可以让助理按授权生成文件或回写任务。Access Grant（访问授权）限定读取、操作和外发范围；需要用户决定具体动作时产生 Approval Request（待决请求）。Execution Evidence（执行证据）把实际动作、使用的来源和交付物关联起来。简报准备完成即可交付这项委托，客户收到答复才完成用户的后续工作。

Local First（本地优先）体现在用户持有工作上下文、记忆、凭据及记录。使用云端推理时，读取本地资料、向特定 Provider 发送资料、修改远端任务分别受授权约束。切换推理配置后，apilot 仍持有自己的任务、委托和记忆。

## 产品入口与开放边界

| 入口 | 用户操作 |
| --- | --- |
| 工作台 | 组织个人视角下的进展、需要判断的问题和可审阅产物。 |
| 任务 | 跨平台搜索、编辑和回写任务。可组合筛选条件、将常用筛选保存为视图，或从当前条件发起关注。在详情中处理映射、绑定和关联。 |
| 连接 | 管理具体连接、同步范围、能力和同步状态。 |
| 全局对话框与对话记录 | 带入当前工作上下文，交代、分析、续聊。 |
| 设置 | 管理 AI Provider、助手库和插件。知识库、写作库和记忆系统暂放在助理配置。 |
| CLI（命令行接口） | 在同等授权下向 Agent 开放完整业务能力，包括查询、同步、委托和结果核对。 |

Open Protocol（开放协议）约定独立程序如何交换对象、原生属性、变更及回写结果；插件方案约定第三方如何提供、安装和管理扩展。公司内部平台可以通过连接器声明自己的字段和图文读写能力，个人配置的连接再决定接入哪些项目。推理服务配置选择模型与推理目标，任务平台连接选择业务数据来源。

## 三层架构与首个对外版本

基本框架、平台连接器、Agent 能力构成三层架构。内部可以按依赖顺序建设。首个对外版本要贯通三层，后续版本可以增加来源、扩展同步能力和提升助理分析质量。

| 层次 | 首版要让用户体验到的能力 |
| --- | --- |
| 基本框架 | 在 macOS 工作台、任务和连接中查看本地工作数据，支持筛选、关注和同步状态。CLI 在同等授权下使用业务操作。 |
| 平台连接器 | 至少接入一个真实工作来源，通过标准插件约定提供对象、本人身份、原生属性、读写和变更发现能力。Syncer 核对来源变化和本地回写。 |
| Agent 能力 | 通过 Pi 和用户选择的推理服务分析已同步资料，给出可追溯到来源的反馈或推荐动作。用户可以选择动作，也可以忽略该条反馈。 |

建议用个人 Obsidian Tasks 演示整条路径。在已有笔记中新添带高优标记的待办，Syncer 增量读入后，工作台呈现新增与高优，助理结合章节背景给出建议。用户忽略建议后仍可在任务列表找到待办；在 Obsidian 中勾选完成，apilot 自动呈现这次进展。对于支持 Webhook 的来源，另验证重复投递、断线漏收后恢复，核对任务状态和提醒次数。具体首发连接器组合待定。

## 仍待决定的边界

- 两个已绑定任务的状态同时改变时，主对象是否具有冲突裁决权，以及不同字段是否允许不同规则。
- 一个来源对象删除、失去权限或暂时无法读取时，映射状态和保留的个人上下文应怎样呈现。
- 知识库与外接记忆系统保存了同一项约定时，哪一方负责纠正和删除，以及怎样让下一次推理使用最新版本。

现有实现可对照[本地架构](architecture.md)。私人助理功能草案 `003-pi-personal-assistant`记录了 Pi、推理配置、委托、记忆、授权与运行的早期范围。
