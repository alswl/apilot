# Now 会话管理设计

## 侧栏

Now 下方显示「置顶」「最近」和「所有会话」。置顶项按手动顺序排列；最近项最多显示 10 个未归档、未置顶的会话，按最近打开或收到消息的时间排序。收起 Now 会话组后，仍可从「Now」回到当前会话。

把最近会话拖到置顶区即可置顶，在置顶区拖动可排序。把置顶会话拖回最近区即取消置顶，按最近活动重新归位。右键菜单提供「置顶／取消置顶」「上移／下移」「重命名」「归档」，让键盘也能完成拖拽对应的操作。正在生成回复的会话可置顶或重排，回复继续归入原会话。

## 所有会话

点「所有会话」在 Now 主内容区查看完整列表。顶部提供搜索和「全部／已归档」筛选，每行显示标题、最近活动时间和一行消息摘要。在本地搜索标题与消息正文，命中正文时显示相关片段。未输入关键词时可直接浏览全量历史。

点击或按 Return 打开选中会话。归档会话提供「重新打开」，恢复原对话、草稿和阅读位置，并进入最近列表。归档保留历史；恢复的会话按最近活动排序，可以再次置顶。在会话中返回「所有会话」时恢复原搜索、筛选和列表位置。

## 待我评审的 GitHub PR

用户打开 Now 时可判断哪些 PR 正在等自己评审。消息列的第一组显示 PR 标题和 `owner/repository #number`。点一行或聚焦后按 Return，在默认浏览器打开 GitHub 的 PR 页面。回到工作台时仍在原会话。该组使用 Now 原有滚动区，和简报、会话输入及全局助理各自保持原有行为。PR 数据只在当前 Now 页面内存中展示，独立于任务查询、Issue 写入及会话消息。

首版使用同一个 GitHub 账号在 Apilot 中已连接、启用且未暂停的仓库。GitHub App 的有效范围由用户权限、安装范围及已批准的 Pull requests 读取权限共同决定，私有仓库也遵循此规则。旧版仓库连接继续使用原凭据，GitHub Issues 连接器通过只读能力查询并在进程内持有凭据。若连接的账号不唯一，Now 提示检查连接。

Core 核对凭据的用户 ID 与连接档案，从各仓库分页读取开放 PR，并按 GitHub 当前返回的个人评审请求匹配该 ID。提交评审、请求撤销或 PR 关闭后，下次读取移除该条目。作者本人、仅团队请求、普通 Issue 均不进入结果。连接变化或断开时清除旧结果。在 Now 打开期间每两分钟重新读取一次，也可主动刷新。访问不足或临时失败的仓库不会提供历史条目，其他已成功读取的仓库仍可见，并提示结果不完整。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 近期会话达到 10 个 | 侧栏首次达到上限时自动折叠，重新展开会显示最近 10 项。较早的会话仍可从「所有会话」浏览和搜索 |
| 拖入置顶区并交换顺序 | 置顶顺序按拖拽结果变化；取消置顶后按活动时间回到最近列表 |
| 搜索一段旧对话里的原话 | 搜索结果显示命中片段，打开后定位到命中的消息 |
| 归档未写完的会话，再重新打开 | 恢复原历史、草稿和阅读位置，不创建重复会话 |
| 同一账号在两个已连接仓库都有同号待评审 PR | Now 显示两条，分别打开对应的 GitHub PR |
| 提交评审、撤销个人请求或关闭 PR | 刷新后条目消失，重新直接请求后条目可再次出现 |
| 仓库访问撤销或 PR 权限不足 | 刷新后只显示可重新确认的结果，提示权限问题或覆盖不完整 |
