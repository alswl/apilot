# macOS 工作台组件评审

范围为浅色 macOS MVP、现有 MyGo 共享组件、工作台原型，以及正式 App 已复用的定时任务行。以下为待实施的设计建议。顺序按对用户决策的影响排列。

## 第一批 · 正确打开、核对、操作同一个对象

| 组件 | 当前体验 | 建议和验收场景 |
| --- | --- | --- |
| 任务表与 Inspector | 切换到「支付发布」后，右侧仍能编辑已被筛掉的 Obsidian 任务。收起详情时行的选中色消失。窄窗的方向键改变行选择也会触发打开详情。 | 用稳定 ID 保存行选择，另行处理打开、收起。筛掉当前任务就关闭对应详情。860 pt 窗口可以用方向键浏览、Return 打开、返回后继续从原行浏览。 |
| 表格列 | 截止日用显示字符串排序，「11 月 10 日」排在「11 月 2 日」前。同一天的回写提示也参与比较。 | 日期、优先级列分别按日期值、优先级顺序排序。用跨月、无日期、同日待回写的样例检查两个排序方向。保留 MyGo Table 的列头、滚动与选区。 |
| 建议与依据 | 简报引用了客户会议和验收记录，点「查看依据」只打开验收标准。详情勾选关注后，简报可以同时出现「正在关注」和「关注退款验收」。 | 在对应判断下面列出可打开的「客户会议 › 跟进事项」「支付改造 › 验收标准」。每条引用显示来源与位置。详情和简报共用同一关注操作；从任一入口采纳后，另一处立即显示已关注，忽略仍只作用于当条分析。 |
| 回写字段 | 窄窗等待回写时只见拟写日期。结果未知时，面板只显示一句等待提示。 | 同一字段并列展示「来源已确认」和「拟写入」。待确认保留两值，冲突可选其一，结果未知可核对来源。宽窄窗都能回答“原值是什么、我改了什么、下一步能做什么”。 |
| 助理对话 | 全局对话发送后清空问题，只保留一段回答。「恢复最近对话」按当前任务重新生成文本，首次使用也能点。 | Now 与弹窗复用消息序列呈现，各自绑定会话和上下文。用两个任务各问两轮，关闭再打开，核对原问题、原回复和引用。没有历史时隐藏恢复动作。 |

## 第二批 · 用统一组件承载视觉和交互细节

| 组件 | 改进 | 验收场景 |
| --- | --- | --- |
| Now 简报消息 | 保留聊天阅读宽度。主建议、依据、顺带告知的进展分别成段。突出一个主要动作，「查看依据」落在相关句子下，「忽略这条分析」作为较轻的次要操作。 | 首屏可指出该关注什么、理由来自哪里，然后直接选择动作。后续进展继续进入同一对话。 |
| 连接行 | 标题优先用用户认识的连接实例名（如「支付发布」），连接器类型和范围作为副标题。最近确认紧邻健康状态，身份、能力放在展开区。 | 放入两个同类型工作区及一个离线来源，能定位异常实例，看到数据截至何时，并打开该实例的任务。 |
| 定时任务行 | 共享行向辅助技术提供任务名、计划和最近运行结果，并表达当前选中态。运行按钮单独命名，包含目标任务。预览注明禁用的实际原因。 | 两条任务都叫「运行」的动作仍可按目标区分。用键盘和 VoiceOver 分辨暂停、上次失败和按钮禁用，逐一核对正式 App 与原型。 |
| 组件预览 | 复用页面级字段和控件组合。当前预览详情手写了两个截止日，恰好掩盖了实际详情缺少确认值的问题。 | 首先覆盖表格的 0、1、30 行和长标题，详情的待确认、冲突、未知，消息的多引用和两轮追问。用同一份样例检查 860 和 1190 pt 两种窗口。 |

## 验证依据

- 视觉走查使用任务、Now、连接和组件预览截图。键盘和辅助功能结论包含源码审查，打包 App 的 VoiceOver 实机走查待做。
- 使用临时 MyGo headless 场景复现日期升序错误及筛选后详情滞留。现有 mockup 和 UI 测试通过。
- 相关实现集中在 `internal/ui/components/{collection,conversation,inspector}.go`、`internal/ui/workbench/{workbench,now_chat,component_gallery}.go` 和 `internal/ui/bootstrap.go`。
